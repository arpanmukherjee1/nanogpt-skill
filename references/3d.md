# 3D model generation (GLB)

**Status:** not in the public docs or OpenAPI spec, but verified (Sept 2026) from NanoGPT's own web-app code - the 3D generate handler and its built-in "show API request" panel, which uses an `x-api-key` header - and a live unauthenticated price quote that matched the catalog.

## Discover
`GET /api/v1/3d-models?detailed=true` (no key). Fields:
- `capabilities`: `model_3d_generation`, `text_to_3d`, `image_to_3d`
- `architecture.input_modalities` - text and/or image (some models accept several views of one object; the description says so)
- `supported_parameters.parameters` - request keys with `label`, `description`, `type`, `options`, `default`; descriptions often state price add-ons (texture size, PBR, rigging, animation, polygon count)
- `description`, `label`, `tags` - textured vs. geometry-only, topology quality, rigging/animation support, prompt length limits, typical speed

## Read pricing
- `pricing.per_run` (default) and `pricing.per_run_by_variant` with `default_variant`. Variant names encode setting combinations (resolution, texture, PBR, rigging, animation, quality tier) - map the planned parameter values to the matching variant.
- Parameter descriptions may add surcharges not captured by the variant name - include them.
- Quotes: send the exact submit body to the submit endpoint without a key and with the quote header (see `scripting.md`); this returned exact prices in testing.

## Choose
- Input: text only, one image, or multiple views.
- Output needs: geometry-only draft vs. textured; PBR/UVs; polygon budget and topology (game engine, printing, preview); rigging/animation.
- Draft first with a cheap geometry-only or low-resolution option when the shape is uncertain; then pay for the textured/high-detail final.
- Typical durations range from under a minute to many minutes - factor into time estimates and poll timeouts.

## Call - shares the video job endpoint
Submit: `POST /api/generate-video`
`{model, prompt?, imageDataUrl?, images?, <parameter keys from supported_parameters>}`
- Text-to-3D: send `prompt` without an image. Image-to-3D: send `imageDataUrl` (data URL or public URL). The server picks the text or image route from whether an image is present; prompt-length limits apply per model.
- Multi-view models: also send `images` as an array of view URLs/data URLs.
- Response: `runId` (or `requestId` / `id`) and pre-charge `cost`; occasionally the result is already present.

Poll: `GET /api/video/status?requestId=<runId>`
- `COMPLETED` → GLB URL at `data.output.model_url` (fallbacks seen in client code: `output.video_url`, `output.video.url`, or the same keys at the top level). Download immediately.
- `FAILED` → report the error; check refund status before any re-run.

If this shape stops working, re-verify rather than guess: load `https://nano-gpt.com/models/3d`, fetch the site's JavaScript chunks, and search them for the 3D generate handler (strings such as `model3d` and the fetch call it makes). Then update this file.

## Pipeline notes
- Image input quality decides the result: single isolated object, full object in frame, plain background, even lighting, minimal occlusion. For multi-view, consistent scale and lighting across views.
- Output is GLB; convert locally if the user needs another format and say which tool is used.
